# 错误上报到 FC 与 SLS（设计提案）

状态：proposed，仅设计，2026-10-22。下列配置、接口和云资源均未因本文而实现或部署。当前 `abx` 没有这个通用错误上报服务；技能安装指南中的遥测说明指外部 skills 安装器。[English](../../en/design/error-reporting.md)。

## 目标与归属

CLI 能观察到的各类失败都应有统一的结构化上报入口，用户可在首次执行前关闭。上报不能改变命令退出码、stdout/stderr、终端行为或业务重试。不能承诺“每条错误必达”：断网、SIGKILL、OOM、模块加载前崩溃、用户关闭、队列过期都会丢事件。

CLI 仓库负责采集、事件合同、脱敏、配置、后台发送器，并在拟议的 `services/error-ingest/` 下维护后端与 IaC，使用独立 CI 和部署身份。接收服务独立于 Registry 和官网函数；它们只发布设置和隐私说明。SDK 应用中的错误需要后续分别接入，不能声称 CLI 能捕获所有外部应用的错误。

## 推荐架构

```mermaid
flowchart LR
  CLI[CLI 统一错误边界] --> Filter[白名单与脱敏]
  Filter --> Spool[受限的本地私有队列]
  Spool --> Worker[限时后台发送器]
  Worker --> Edge[HTTPS 网关：限流与防滥用]
  Edge --> FC[私有 FC 接收函数]
  FC --> SLS[校验后输出 JSON 到独立 SLS]
```

第一版采用**客户端异步发送、接收函数快速同步校验并打印结构化日志**。FC 绑定 SLS，stdout 自动采集；完成输出后返回 202。这仅表示应用已接收，不保证 SLS 已完成持久化或索引。[FC stdout 日志采集](https://www.alibabacloud.com/help/en/functioncompute/context-and-log-format-1)。

若后续需要削峰，保留入口校验，再由入口通过函数角色异步调用私有 worker，设置重试次数、事件寿命和失败目的地。FC 支持 `X-Fc-Invocation-Type: Async`，队列接收后就可返回 202；这不表示函数内部的日志校验已经执行。[FC 异步调用](https://www.alibabacloud.com/help/en/functioncompute/fc-asynchronous-invocation)。

因此不能只开放匿名异步函数、等 worker 才判断真假：非法流量可能已经入队并产生费用。网关必须拒绝或移除客户端传入的 FC 调用控制头，避免绕过同步校验。FC 原始入口必须私有化或验证网关身份，不能只保护自定义域名而留下直连绕过。部署测试须验证这一点。[FC HTTP 触发器防护](https://www.alibabacloud.com/help/en/functioncompute/configure-an-http-trigger-for-a-function-and-invoke-the-function-by-using-http-requests)。

## 用户控制

拟议接口，当前尚不可用：

```bash
abx config set diagnostics.enabled false
abx config get diagnostics.enabled
abx config set diagnostics.enabled true
ABX_DIAGNOSTICS=0 abx template deploy ./codex -y
```

用户文件 `~/.abx/config.toml`：

```toml
[diagnostics]
enabled = false
```

同时尊重 `DO_NOT_TRACK=1`、`DISABLE_TELEMETRY=1`。任一受支持来源显式关闭时，优先于其他来源的开启。该设置属于宿主，独立于 Provider。项目 YAML、插件、项目 dotenv 不能修改接收地址；正式构建固定 HTTPS 域名，管理员自定义构建需遵守同样的校验要求。

建议默认开启最小安全事件，安装页、帮助和首次普通错误给出明确说明及关闭命令。首次提示仅用于普通终端的 stderr，不污染 JSON、quiet 或 MCP 协议；这些模式通过安装和帮助文档告知。帮助、补全、版本、模块导入都不能发网络请求或创建身份文件。

先解析关闭策略，再决定是否入队、注册和启动发送器。执行关闭命令本身不触发上报；取消当前安装的待发送任务，删除本地待发送事件和身份/令牌缓存。通过共享锁与代际标记避免删除队列时发送器仍在工作，并在发请求前再次检查。已经发送的数据无法靠本地关闭追回。

配置损坏或无法读取时，上报默认关闭，原命令仍显示原有配置错误；不能为了报告配置错误而依赖成功加载全部配置。布尔 false 不可视为缺省。未来若增加详细诊断包，须单独明确同意并在本地预览；开启最小事件不等于上传原始日志。

## 采集边界

| 错误来源 | 采集位置 | 规则 |
| --- | --- | --- |
| 原生命令、配置、用法错误 | 框架错误边界与 `handleErrors` | 每次操作最终失败只记一次，保留原格式与退出码 |
| 内嵌标准 CLI | 固定上游源码构建中的显式失败 hook | 获取分类/代码，不抓取终端原文；重放 lockfile 和来源检查 |
| Provider、插件、构建部署 | 宿主适配器与部署结果 | 只取阶段和安全 ID；插件错误文本/输出视为不可信 |
| MCP 工具错误 | 工具结果边界 | 安全操作 ID 与分类，不上传 JSON-RPC 参数或协议内容 |
| 后台任务、远程命令非零退出 | 任务结果适配器 | 上报 `remote_exit` 与整数状态，不上传命令和输出，不当成 CLI 崩溃 |
| 未捕获异常、Promise rejection | 最早可安装的进程边界 | 只记 `internal_error`；尽力同步入队，仍按原方式退出 |
| 主动取消、Ctrl-C | 显式取消结果 | 默认不上报为错误 |
| 最终已恢复的内部重试 | 重试适配器 | 最终失败汇总次数，不逐次重复上报 |

在动态加载 `abx_main` 前安装采集器。操作 ID 和错误对象标记去重；并发 MCP 使用 `AsyncLocalStorage`，不能共享一个全局操作 ID。成功操作无需采集。发送器自己的失败不递归上报；不能用 uncaughtException 处理器强行继续业务。加载前崩溃等不可观察失败明确列为限制。

## 最小事件与隐私

拟议 `POST /v1/diagnostics/events`，不是现有接口。UTF-8 JSON，每次一个对象，不压缩，最多 8 KiB、深度 4。要求 `Content-Type: application/json`；拒绝未知字段、重复 JSON 键、错误类型、非法 UTF-8 和非有限数。流式读取也执行硬大小上限。没有附件或任意 metadata。

| 字段 | 类型与限制 | 来源 |
| --- | --- | --- |
| `schema_version` | 整数 1 | 固定协议 |
| `event_id` | UUIDv4 | 每事件生成，重试不变 |
| `occurred_at` | RFC3339 UTC | 客户端时钟；另记服务端接收时间 |
| `cli_version` | 合法版本，最多 32 字符 | 构建常量，后端视为客户端声明 |
| `runtime` | Node 主版本、OS/CPU 枚举 | 不含主机名、用户、精细系统指纹 |
| `command_id` | 白名单命令路径，最多 80 字符 | 不含 argv 或任意插件操作名 |
| `provider_id` | 已知 ID 或 `custom`，最多 64 字符 | 不含本地路径、源地址或客户命名 |
| `category` / `error_code` | 枚举 / 已知代码或 `unknown` | 用法、配置、认证、能力、网络、构建、远程退出、内部错误 |
| `stage` / `exit_code` | 枚举 / 有界整数 | 当前操作的结果 |
| `missing_fields` | 最多 12 个白名单字段 ID | 只有名称；自定义字段归为 `custom` |
| `retry_count` | 整数 0–10 | 汇总次数 |
| `stack_frames` | 可选，最多 8 个包内模块/函数 ID | 仅内部错误，不含完整堆栈 |

第一版不上传自由文本 `message`，后台根据错误码和模板生成可读说明。禁止原始参数、远程命令/输出、提示词、生成代码、文件、工作目录、用户/主目录路径、仓库地址、环境值、凭据、云账号/资源 ID、API 端点、HTTP 内容/头及任意 Provider 错误原文。对秘密做哈希并不等于匿名化。分组指纹只计算分类、代码、规范命令、包内帧。

先按白名单构造事件，再做第二层凭据模式、URL、路径、控制字符及当前已知秘密值过滤；无法确定的字段直接删除。服务端再次校验，只使用 JSON 序列化输出，防止日志注入。测试覆盖 Error.cause、AggregateError、JWT、AK/SK、签名 URL、Windows/Unix 路径、恶意 Unicode 和换行。

安装身份只是化名标识，会在有效期内关联事件，不能宣称完全匿名；不与客户账号建立关联。敏感调试信息仅按已有显式本地日志规则处理。

## 异步发送、性能与丢失边界

前台不等待 DNS、注册、HTTP 或日志服务。失败时将最多 8 KiB 的事件原子写入 `~/.abx/diagnostics/`，目录 0700、文件 0600，拒绝符号链接和不安全归属。队列上限 100 条、1 MiB、24 小时；超限丢最老事件，只保留本地计数。磁盘满、权限错误、队列损坏不会覆盖业务错误。

文件写入和启动子进程仍有成本，不能承诺零性能影响。目标为参考硬件前台额外 p95 ≤10 ms，分别测 npm/SEA 的冷暖路径；达不到则选择仅内存尽力发送，并如实记录丢失。

仅错误出现后才启动一个脱离前台并 unref 的限时发送器，忽略 stdio，最小环境、单安装锁、不经 shell。分别支持 npm 入口与 SEA 可执行文件，验证 Windows。HTTPS 校验证书、不跟随重定向、固定正式域名，不携带任何云凭据。不能启动时留待之后命令发送，不安装常驻服务或定时任务。帮助/版本不能唤醒发送器；其他命令只有在策略解析后且满足启动预算时才能清空旧队列。

发送器总寿命 ≤5 秒，单请求 ≤1 秒，每轮最多 3 个请求（包括注册）。网络、5xx、429 使用随机退避，在后续运行重试；在期限内尊重 Retry-After。普通无效 4xx 丢弃；401/403 仅允许重新注册一次，不循环。每次重试保持 event_id，更换 nonce/时间/签名。收到 202 删除本地事件。不能承诺 exactly once，也不能保证 FC stdout 已被 SLS 持久化。

## 认证、签名与防攻击

HTTPS 解决传输保密。若将来要求网关不可见正文，再选经过审查的混合加密格式和接收公钥轮换。最小无自由文本事件的 v1 不必增加自制加密。加密和签名都不证明日志内容真实。

不在公开 CLI 内置统一 HMAC 密钥、AccessKey 或永久 token。内嵌服务器验签公钥可以公开，私钥留在后端。攻击者也能安装官方 CLI 或生成自己的安装密钥，因此安装签名只证明持有该密钥，不能证明运行未修改的官方二进制。

拟议注册/发送过程，全在后台：

1. 安装首次产生可报告错误时，后台在私有目录创建 Ed25519 密钥对；不采集硬件指纹、不需要登录或 Sandbox 凭据。身份/令牌缓存最多 30 天轮换。
2. 拟议 `POST /v1/diagnostics/enroll` 仅接收公钥和协议能力。网关按可信网络来源及全局预算限制注册，后端签发 24 小时 token，包含 issuer、audience、expiry、jti、随机安装 subject、公钥指纹和 `diagnostics:write` scope。不能访问云账号。不能审计好绑定 JWT 时改用不透明 token。
3. 客户端对下列 UTF-8 字节签名，末尾没有换行：`abx-diagnostics-v1\nPOST\n/v1/diagnostics/events\n<token-jti>\n<unix-seconds>\n<nonce>\n<lowercase-hex-sha256-of-body>`。nonce 是 128 位随机数，以不带填充的 base64url 表示。请求头为 `Authorization: Bearer <token>`、`X-Abx-Diagnostics-Timestamp`、`X-Abx-Diagnostics-Nonce`、`X-Abx-Diagnostics-Signature`（Ed25519 签名采用无填充 base64url）。Authorization 最多 2 KiB，自定义头各最多 128 字节，均不放 URL。
4. 服务端验证签发方、受众、scope、有效期、公钥绑定、签名、±5 分钟时间窗口和严格 schema。共享存储以原子 insert-if-absent 记录 `(token-jti, nonce)`，TTL 10 分钟；event_id 去重 24 小时。完整校验后、打印前原子保留两种去重记录。不能用单实例内存表代替。存储故障返回有界 503 且不打印原文；时钟偏差最多丢失/延迟上报，不影响业务。

该流程阻止捕获请求的重放，无法阻止攻击者批量注册或伪造合法格式的内容。日志统一标记 `trust=anonymous_unverified`，不用于计费、授权、处罚或安全事实判断。

初始可调运营限额：每安装 10 条/分钟、突发 20；每网络桶 100 条/分钟、突发 200；每网络桶 5 次注册/小时；请求最多 8 KiB。共享 NAT 可能丢诊断，需观测后调整。网关仅信任受控代理转发地址，使用每日轮换的服务端 HMAC(IP) 做限流，应用日志不存原始 IP。访问日志须隐藏正文、Authorization、查询参数和原始 IP；确需安全日志时单独授权、隔离并短期保存。

网关在进入 FC 前限制方法、路径、大小和速率；另设全局接收预算与紧急停收开关。灰度建议每天最多 10,000 条有效事件、100,000 次总入口请求。这些是待配置并测试的数量上限，不是货币账单硬保证。还需配置 WAF/网关额度、FC 并发/实例上限、执行超时与重试上限。达到预算 50/80/100% 告警，达到上限停收。无效请求只计原因桶，不输出原请求体；服务自身错误不递归上报。

## SLS、权限与运营

部署时选择地域、专用 SLS project/logstore、FC、域名并写入 IaC；本文不创建资源。FC 使用只允许投递到目标 Logstore 的 RAM 角色，入口只允许网关调用，后续异步 worker 只允许入口角色调用。部署凭据不下发客户端，没有公开日志查询接口。

每事件一行 JSON，包含固定标记 `abx_diagnostic_v1`、接收时间、事件 ID、化名安装身份及不可信等级。只索引版本、类别、错误码、命令、指纹等必要字段。灰度保留 7 天，生产最多 30 天，维护者按最小权限读取并审计，不关联客户身份。函数及网关日志均不能打印认证头。发布前说明保留期、联系/删除流程；本地关闭不会自动删除历史服务器记录。

stdout→SLS 不是持久化事务。灰度须测重启、采集故障中的丢失、重复和延迟；若要求更强可靠性，应先写受支持的持久队列、确认接收后再异步投递 SLS，保留事件 ID 与失败指标。这需要额外成本，不能靠“函数打印了”声称必达。

## 实施阶段和验收

1. 先实现字段合同、宿主配置注册、策略解析、纯脱敏器及各错误边界 hook；远程发送保留发布开关。内嵌 CLI 修改其可重放源码构建流程，不直接修改生成 runtime。
2. 实现独立后端、注册/签名/重放/限流与 IaC，验证直连绕过、恶意请求洪泛、最小 IAM 和真实 SLS 记录，限额灰度。
3. 实现有界队列/发送器和 npm/SEA 包装；验证首次执行前关闭、并发开关竞态、队列恢复、取消、文件权限及离线行为。
4. E2E 覆盖原生命令用法/配置、内嵌 parser/认证、Provider/网络/构建、MCP、远程非零退出、早期崩溃；覆盖所有输出模式与 CI。验证关闭后连注册/延迟重试都零请求；检查零秘密发送/存储。加入代理、TLS、重定向、时钟偏差、去重、密钥轮换、批量注册、预算停收、DNS 卡住、磁盘满、半写文件、日志故障和发送器被杀的故障注入。实测延迟。
5. 发布中英隐私、设置、帮助、安装说明；按 1%→10%→100% 灰度观察数量、延迟、丢失和费用。远端开关只能停收，不能覆盖本地关闭强制开启。回滚同时停入口与客户端发布开关，并让旧队列过期。

完成条件：真实 HTTPS→FC→SLS 脱敏事件读回、关闭后零请求、原命令输出/退出码无变化、性能达标且防滥用验证通过。记录实际域名/地域/资源、预算负责人、保留期和验证证据。在这些条件满足前，该功能保持设计提案状态。
