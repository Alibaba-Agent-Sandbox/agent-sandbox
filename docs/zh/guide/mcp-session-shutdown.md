# MCP 请求在会话结束时才完成

MCP 会话可能在后端仍创建沙箱或连接客户端时结束。管理器会原子协调会话关闭和句柄登记：
如果创建结果较晚返回，会取消请求并删除这个新建沙箱；如果连接到已有沙箱的结果较晚返回，
会取消请求并只关闭客户端句柄，保留已有沙箱。

清理遵循请求的资源归属。显式访问已有沙箱不等于把删除权交给当前会话。用户明确授权的
`kill_sandbox` 仍是独立删除操作，已接受的后台任务保留规则也保持原有范围。

断开后若无法确定后端创建结果，应先按实际返回的 ID 或本轮资源记录核对，再决定是否重复
写入。请求取消与清理失败是两个结果；删除失败时，平台生命周期仍限制资源的最终存活时间。

使用 Streamable HTTP 时，向 `DELETE /mcp` 传入会话的 `Mcp-Session-Id`，并使用初始化时的
Bearer 鉴权。HTTP 200 表示清理成功；HTTP 503 表示清理未完成，应保留会话 ID 并重试同一个
DELETE。重试只处理清理失败的句柄，不重复删除已经清理的资源。清理期间，该会话的工具请求
返回 HTTP 409。借用或明确保留的沙箱始终只关闭连接，重试也不会删除这些资源。

原生删除失败后，SDK 客户端仍可用于重试；云端确认删除后若本地连接清理失败，再次重试只清理
本地连接。SDK 调用方若决定不再重试，可调用 `close()` 释放本地连接，这不会删除云端沙箱。

空闲过期使用相同规则。清理失败的会话仍计入会话数量上限；再经过一个已配置的 Session TTL
间隔后，后续请求会重新尝试清理。显式 DELETE 可以立即重试。过期清理由请求触发，没有独立
后台定时器。

恢复记录保存在当前服务进程的内存中，进程重启后不会保留；剩余资源需通过 Provider 的沙箱 ID
和生命周期设置管理。关闭过程会等待已经受理的创建、连接请求返回句柄，但不保证所有运行中的
工具或外部副作用都已停止。服务进程关闭时会报告清理失败，不会把失败当成释放成功。

HTTP 端点接受 `MCP-Protocol-Version: 2025-06-18`。显式传入其他版本或无效版本时，
在执行工具、过期清理或删除之前返回 HTTP 400。省略此请求头时保留会话已协商的行为；
`/health` 不要求协议请求头。来源与鉴权检查仍先执行。
