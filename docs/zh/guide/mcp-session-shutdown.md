# MCP 请求在会话结束时才完成

MCP 会话可能在后端仍创建沙箱或连接客户端时结束。管理器会原子协调会话关闭和句柄登记：
如果创建结果较晚返回，会取消请求并删除这个新建沙箱；如果连接到已有沙箱的结果较晚返回，
会取消请求并只关闭客户端句柄，保留已有沙箱。

清理遵循请求的资源归属。显式访问已有沙箱不等于把删除权交给当前会话。用户明确授权的
`kill_sandbox` 仍是独立删除操作，已接受的后台任务保留规则也保持原有范围。

断开后若无法确定后端创建结果，应先按实际返回的 ID 或本轮资源记录核对，再决定是否重复
写入。请求取消与清理失败是两个结果；删除失败时，平台生命周期仍限制资源的最终存活时间。

维护者可运行真实句柄验收：

```bash
npm run build
node e2e/skill-mcp-shutdown-acceptance.mjs --output ./mcp-shutdown-new.json
```

通过环境变量提供已有沙箱 API Key 和地址。场景实际执行 Express 创建、连接、命令和删除，
测试钩子只延迟真实 SDK 句柄返回并控制锁的排队顺序，确定性重现竞态，不模拟云端响应。
验收会独立确认新建资源404、被借用沙箱仍能执行业务命令，以及最终两个本轮测试沙箱都被删除。
