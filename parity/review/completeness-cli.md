# Completeness review: CLI port (Python `abx` -> `cli/src`)

Method: mechanical inventories, not sampling. Everything below is regenerated by
`ORIG_REPO=<original python repo> ORACLE_VENV=<oracle venv> bash cli/parity/review/inventory/run_all.sh`
(offline, skips cleanly when the oracle is absent). Raw outputs are in `cli/parity/review/inventory/out/`.

* Python side: `py_inventory.py` (stdlib `ast`) over the original `src/` -> 104 modules, 1579 symbols, ~7000 string
  literals (each tagged message / path / env / endpoint / identifier), 72 env reads, exit sites.
* Node side: `ts_inventory.mjs` (TypeScript compiler API) over `cli/src` -> 112 files, 20107 literals, 66 env reads.
* Click surface: `click_tree.py` (live introspection of the oracle) vs `click_tree.mjs` (live introspection of
  `dist/framework`), compared field by field by `click_tree_diff.py`.
* Comparison: `cli_compare.py` (camelCase mapping, relocation check, literal matching modulo placeholders/formatting).

## 6. Exit codes

Exit sites (`sys.exit`, `raise SystemExit`, `ctx.exit`, `EXIT_*` constants): Python 63, Node 62 per module
(`inventory/out/exit-sites.txt`). The single delta is `cli/commands/mcp`: Node has one extra `sysExit(3)`
(`src/cli/commands/mcp.ts:939`, uvicorn start-up failure). In Python that exit comes from inside `uvicorn.run` itself
(uvicorn exits with status 3 when it cannot start), so the observable exit code is identical; it is the documented
"uvicorn replaced by `node:http`" gap. `x if result.success else 1` is equivalent to `result.success ? 0 : 1`.
All of exit codes 0-6 and the `EXIT_*` mapping in `cli/main` (17 sites) match one to one. No exit code is lost.
