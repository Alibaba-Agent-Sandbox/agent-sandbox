Usage: abx deploy [options] [PATH]

Publish a template project: build, push to ACR, register the template (same as
'abx template deploy').

Runs one publish path. No LLM is involved.
PATH is the template directory (default: .). --build auto (the default)
uses a Dockerfile when one is present, and otherwise template.yaml build
steps. dockerfile mode builds and pushes an image, then waits until the
template is ready. steps mode sends base.image and sandboxConfig.steps
and does not use Docker or ACR. template.yaml supplies the template name
and resources.

A missing PATH offers template creation and continues after confirmation.
--yes/-y or CI mode creates a Python template project without prompts.
Existing project files are kept.

To author the files first, use 'abx template scaffold': --adopt for an existing
project, a natural-language description to generate the files, or
--template for a scaffold.

Accepts every option of 'abx template deploy' (--acr-namespace,
--alias, --yes, -v/--verbose, ...). The ACR namespace and AccessKey are
set with 'abx config init --build'.

Examples:
  abx deploy --acr-namespace my-ns           # publish ./ as a template
  abx deploy ./my-template --yes             # non-interactive
  abx --json deploy ./my-template -y         # JSON on stdout; id is TemplateID
  abx deploy ./my-template -v                # with debug logs

Typical flow:
  abx template scaffold --adopt .                      # 1a. author from a
project
  abx template scaffold --prompt "a python data science env"   # 1b. generate
from a description
  abx deploy ./<name> --acr-namespace my-ns       # 2. publish
  abx create <TEMPLATE_ID>             # 3. launch a sandbox

Related commands:
  abx template scaffold          Author Dockerfile / template.yaml
  abx template deploy DIR    The same pipeline with a required DIRECTORY
  abx create "DESCRIPTION"   Generate + publish + launch in one go

Options:
  --acr-registry <ACR_REGISTRY>            ACR registry host
  --acr-namespace <ACR_NAMESPACE>          ACR namespace (env: ACR_NAMESPACE, or set in .env file)
  --acr-repo <ACR_REPO>                    ACR repository name (defaults to template.yaml name or dir name)
  --acr-username <ACR_USERNAME>            ACR login username (default: ALICLOUD_ACCESS_KEY_ID)
  --acr-password <ACR_PASSWORD>            ACR login password (default: ALICLOUD_ACCESS_KEY_SECRET)
  --acree-instance-id <ACREE_INSTANCE_ID>  ACR EE instance ID (cri-...)
  --vpc-id <VPC_ID>                        VPC ID for ACR EE
  --vswitch-ids <VSWITCH_IDS>              Comma-separated VSwitch IDs
  --security-group-id <SECURITY_GROUP_ID>  Security group ID
  -a, --alias <ALIAS>                      Template alias
  -t, --tag <TAG>                          Docker image tag
  --platform <PLATFORM>                    Target platform
  --cpu <INTEGER>                          CPU cores (default: from template.yaml resources.cpu, fallback 2)
  --memory <INTEGER>                       Memory in MB (default: from template.yaml resources.memory, fallback 2048)
  --start-cmd <START_CMD>                  Container start command
  --ready-cmd <READY_CMD>                  Container readiness check command
  --timeout <INTEGER>                      Build timeout in seconds
  -f, --dockerfile <PATH>                  Custom Dockerfile path
  --build <BUILD>                          Publish path: auto (Dockerfile if present, otherwise template.yaml build steps), dockerfile, or steps [default: auto] (choices: "auto", "dockerfile", "steps")
  --disk-size <INTEGER>                    Disk size in MB (official API only)
  --internet-access                        Internet access (default: platform decides; official API only)
  --no-internet-access                     Opposite of --internet-access.
  --team-id <TEAM_ID>                      Team ID for official API (or env TEAM_ID / E2B_TEAM_ID)
  --envd-inject                            Enable envd injection (default False)
  --no-envd-inject                         Opposite of --envd-inject.
  --generation <INTEGER>                   Sandbox generation (default: template.yaml 'generation'; else 2 when the provider starts the server and commands.py exists; else 1). 1=first-gen (rund), 2=second-gen MicroVM.
  --force                                  If a generation-1 template with this name already exists, delete it and create it again. Without --force, deploy stops and prints 'abx template delete <id> -y'.
  --target-image <TARGET_IMAGE>            Destination image ref for envd copy (auto-derived with random suffix if omitted)
  -y, --yes                                Skip confirmation prompt
  -v, --verbose                            Verbose output (DEBUG level)
  -r, --region <TEXT>                      Region override for providers that declare region (otherwise use the provider default)
  -h, --help                               Show this message and exit.
